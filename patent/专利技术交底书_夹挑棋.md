# 专利技术交底书（中国大陆适用）

## 一、发明名称
一种基于线拓扑索引与连锁转换的棋类对弈处理方法、装置、系统及存储介质

## 二、技术领域
本发明涉及计算机游戏与人机交互技术领域，尤其涉及一种用于网络连线棋盘博弈的规则计算与在线同步处理技术方案，具体包括：棋盘拓扑建模、合法移动计算、连锁吃子判定、人机对战决策以及在线对战一致性校验。

## 三、背景技术
现有网页棋类游戏通常采用网格邻接或逐步几何判断方式实现走子和吃子规则。对于包含横线、纵线及交替斜线的异构连线棋盘，传统实现存在如下问题：

1. 规则计算复杂度高：每次走子都需重复进行几何方向推导；
2. 连锁吃子实现不稳定：多步吃子中容易产生重复转换、漏判或顺序不一致；
3. 在线对战易出现双端不一致：仅客户端判定可能被篡改或产生状态漂移；
4. 动画与状态竞争：在可视化阶段若允许并发输入，容易导致棋盘状态被重复写入。

因此，需要一种可工程化、可校验、可扩展的统一技术方案。

## 四、现有技术缺陷（待解决技术问题）
1. 如何在复杂连线棋盘上快速确定任一点可达移动集合；
2. 如何在“夹”和“挑”两类规则并存时，避免同一步中重复吃子；
3. 如何实现可终止、无死循环的连锁转换机制；
4. 如何保障在线对战中前后端规则一致与回合一致；
5. 如何在动画播放时保证状态原子性与用户操作安全。

## 五、发明目的
提出一种面向5×5交叉点连线棋盘的规则处理框架，通过“线拓扑预建 + 点线映射索引 + 广度优先连锁转换 + 服务端合法性复核”实现高效率、强一致、可视化友好的棋类博弈处理。

## 六、技术方案

### 6.1 总体架构
本方案包含前端执行模块与在线服务模块：

- 前端模块：负责棋盘绘制、用户输入、规则计算、连锁动画、人机策略、在线消息收发；
- 服务端模块：负责房间管理、回合控制、走子合法性校验、状态广播、断连处理。

### 6.2 棋盘拓扑预构建机制
在初始化阶段构建：

1. `allLines`：保存全部有效连线（5条横线、5条纵线、6条斜线）；
2. `ptLines`：以坐标键值（x,y）映射该点所在连线及其在线内索引位置（li, pi）。

由此将后续规则计算由“实时几何推导”转化为“线性数组扫描”，降低运算复杂度并提升稳定性。

### 6.3 合法移动计算方法
对起点棋子 `(x,y)`：

1. 读取 `ptLines[x,y]` 得到该点所属连线集合；
2. 对每条线按索引向正、反两个方向扫描；
3. 遇到非空点即终止该方向；
4. 将经过的空点加入合法落点集合。

该方法实现“沿有线方向任意距离移动且不可跨子”。

### 6.4 吃子判定方法
以落点为中心，针对其所属每条线，执行三类局面检测：

1. 夹（正向）：`me(pi)-enemy(pi+1)-me(pi+2)`；
2. 夹（反向）：`me(pi)-enemy(pi-1)-me(pi-2)`；
3. 挑（跨向）：`enemy(pi-1)-me(pi)-enemy(pi+1)`。

将命中的敌方点坐标加入待转换集合，并使用坐标键去重，防止重复转换。

### 6.5 连锁转换引擎
采用广度优先搜索（BFS）分层处理：

1. 第一层队列初始化为“当前落点”；
2. 对队列内每点计算新吃子集合；
3. 将本层去重后目标统一转换为己方颜色；
4. 转换后的点作为下一层队列；
5. 直至队列为空，连锁终止。

该机制可保证：
- 每层只处理一次同一目标；
- 连锁必然终止；
- 支持“按步动画回放”与“无动画快速结算”两种执行路径。

### 6.6 胜负判定机制
每回合执行：

1. 子数判定：任一方棋子数为0则另一方胜；
2. 无路可走判定：轮到某方时，若其所有棋子均无合法移动则该方负。

### 6.7 人机对战决策机制
在候选走法集合上定义启发式评分：

- 连锁吃子收益（高权重）；
- 目标点中心距离（中心优先）；
- 前进趋势（鼓励推进）。

取最高分集合内随机一解，兼顾可解释性与局内变化性。

### 6.8 在线一致性与安全机制
服务端执行以下控制：

1. 房间人数上限为2；
2. 仅当前行棋方可发送有效走子；
3. 服务端复算移动合法性、路径阻挡、落点占用与连锁结果；
4. 非法请求返回错误消息，不写入状态；
5. 走子成功后向对手广播结果；
6. 房间无人时自动回收。

从而实现“客户端交互 + 服务端仲裁”的双层一致性模型。

## 七、有益效果
相对于现有技术，本发明至少具有以下效果：

1. **计算高效**：拓扑索引减少重复几何判断；
2. **规则准确**：夹/挑/连锁统一于同一线性判定框架；
3. **连锁稳定**：BFS分层与去重避免重复吃子与顺序混乱；
4. **在线可靠**：服务端复核抑制作弊并保证回合一致；
5. **交互安全**：动画期间输入锁定，避免并发写状态；
6. **工程可扩展**：可平滑扩展AI难度、断线重连、对局回放等功能。

## 九、具体实施方式（示例）

### 实施例1：本地对弈执行流程
1. 初始化棋盘状态与拓扑索引；
2. 用户选择己方棋子，系统计算合法落点并高亮；
3. 用户提交落点，系统执行移动；
4. 触发吃子判定并进入BFS连锁转换；
5. 执行子数与无路可走判定；
6. 若未终局则切换回合。

### 实施例2：在线对弈执行流程
1. 客户端发送 `join(roomId)` 进入房间并分配棋色；
2. 行棋方发送 `move(fx,fy,tx,ty)`；
3. 服务端复算合法性并执行连锁转换；
4. 服务端更新当前回合并广播给对手；
5. 对局结束时发送终局状态或认输结果。

### 实施例3：人机对战流程
1. 玩家完成走子后，系统生成AI全部候选走法；
2. 对每候选进行连锁收益估计；
3. 按评分函数择优并执行；
4. 重复执行至终局。

## 十、可替代实施方式
1. 棋盘规模可扩展为 `N×N`，连线集合可参数化生成；
2. 连锁队列可替换为事件流处理，但需保留去重机制；
3. AI可替换为Minimax、MCTS或深度强化学习策略；
4. 通信层可由WebSocket替换为WebRTC数据通道或TCP长连接；
5. 服务端可采用多进程或分布式房间管理架构。

## 十一、建议保护点（供权利要求起草）

### 11.1 独立权利要求方向（方法）
一种棋类对弈处理方法，其特征在于：

- 对棋盘连线进行预构建并形成点线映射索引；
- 基于所述索引执行走子合法性扫描；
- 以落点为中心按夹/挑规则生成待转换集合并去重；
- 采用广度优先分层机制进行连锁转换，直至无新增目标；
- 执行终局判定并切换回合。

### 11.2 独立权利要求方向（系统/装置）
一种在线棋类对弈系统，包括客户端模块与服务端模块，服务端配置为：

- 对客户端走子请求进行回合身份校验和规则复算；
- 在合法时更新房间棋盘状态并广播；
- 在非法时拒绝写入并返回错误。

### 11.3 从属权利要求可选特征
- 连锁转换中的同层去重策略；
- 动画阶段输入锁定机制；
- 启发式评分中的吃子权重、中心权重与推进权重组合；
- 房间空置自动回收机制；
- 重开与认输的同步协议字段设计。

## 十二、术语定义
- 夹：己方棋子与己方棋子在同一直线上夹住一枚敌方棋子；
- 挑：己方棋子插入同一直线相邻两枚敌方棋子之间；
- 连锁：一次转换触发后续新的夹/挑并继续转换；
- 点线映射索引：从棋盘点到连线及在线内位置的映射关系。
